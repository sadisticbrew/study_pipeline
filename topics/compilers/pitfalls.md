## 2026-10-13 chapter 2: "zero-extends" used without explanation
- Kind: confusing
- Wrong or unclear: "Writing a 32-bit name zero-extends the result into the whole 64-bit register" used the jargon "zero-extends" with no definition or plain-language explanation, so the learner had to look it up.
- Correct: When an instruction writes a 32-bit register name such as `%eax`, the processor sets the upper 32 bits of the 64-bit register (`%rax`) to zero, so the register holds the 32-bit result with zeros above it. This is zero extension (widening by filling the new high bits with zeros). 8- and 16-bit writes leave the upper 56 or 48 bits unchanged. Say what happens to the bits in plain words before naming the operation, and mark the term.
- Evidence: F4, F5 (Intel SDM Vol. 1, §3.4.1.1, p. 3-12)

## 2026-10-14 chapter 2: call/ret, prologue/epilogue and recursive frames described but not drawn
- Kind: confusing
- Wrong or unclear: The chapter explained `call`/`ret`, the `fact` prologue and epilogue, and the five recursive frames only in prose, and its one stack figure was a chain of four boxes ("fact(5) frame: ret addr, saved rbp, n=5") that showed neither the 8-byte slots nor where `%rsp` and `%rbp` point, so the learner had to sketch the stack themselves.
- Correct: `call` pushes the address of the next instruction and jumps, so on entry `%rsp` points at the return address; `ret` pops the top of the stack into `%rip`. After the `-O0` prologue (`pushq %rbp; movq %rsp, %rbp; subq $16, %rsp; movq %rdi, -8(%rbp)`) the frame is, from high to low: return address at `8(%rbp)`, caller's `%rbp` at `0(%rbp)` (where `%rbp` points), `n` at `-8(%rbp)`, an unused slot at `-16(%rbp)` (where `%rsp` points), 32 bytes per activation. `leave` reverses it in two steps (copy `%rbp` to `%rsp`, pop `%rbp`). Every recursive frame's return address is the same `imulq` after `call fact`; the saved-`%rbp` chain is what restores each activation's own `n`. When a chapter's mechanism is a stack layout or register state changing across instructions, draw slot-level snapshots with `%rsp`/`%rbp` marked, as HTML-table `.dot` nodes.
- Evidence: F9, F10, F15, F23, F46, F62 (System V psABI, sec. 3.2.2, figure "Stack Frame with Base Pointer"); lab/frames/run.out lines 4-21, 47-58

## 2026-10-16 chapter 3: automata introduced as definitions without a mental model of states and transitions
- Kind: confusing
- Wrong or unclear: "Regular expressions and Thompson's construction" opened with "To run one we turn it into a graph" and defined NFA, ε-transition, accepting state and nondeterminism in one paragraph of terms and margin notes, then went straight to Thompson's recipe and its code; the DFA section then traced lab state numbers and NFA sets the reader had never seen drawn. The roadmap assumed "sets and graphs at an intro discrete-math level", which this learner does not have, so he understood almost nothing and read the edge labels as costs.
- Correct: A state is one situation the lexer can be in, standing for everything it must remember about the characters read so far (being inside the `<` branch of a hand-written loop is the state "seen `<`"). A transition is an arrow whose label is the input character that must come next to cross it; labels are conditions, never costs or distances, and nothing is summed along a path. Accepting states (double circles) mean the input read so far is a complete token; a self-loop lets finitely many states cover names of any length. A DFA has at most one arrow per character from each state (F51). An NFA may have several (on `i`, both IF's and IDENT's machines), and runs by tracking the set of states it could be in (F55): `iffy` gives {start} → {seen i, in a name} → {seen if, in a name} (IF and IDENT both accepting) → {in a name} → … → empty at the space. ε-arrows are followed without reading input (F53) and let rule machines be glued under a new start without disturbing their arrows; with the lab's numbering, `<=` gives {0, 15, 17} → {16, 18, 19} → {20}, and the set {16, 18, 19} behaves exactly like the DFA state "seen `<`", which is the idea of the subset construction (F57). General rule for every chapter: never assume a foundational mental model is in place because its terminology has been defined. Establish the prerequisite through a concrete mechanism the learner already knows, a small labelled diagram where useful, and a character-by-character (or step-by-step) trace done by hand, before any construction algorithm, abstraction or code; then make the later algorithm reuse those same traced examples and numbers.
- Evidence: F47–F57 (Cox, "Regular Expression Matching Can Be Simple And Fast", sections Finite Automata, Regular Expression Search Algorithms, Caching the NFA to build a DFA); lab/automata/automata.py:87-125 (NFA states 0–20 as drawn); lab/automata/run.out lines 5-17
