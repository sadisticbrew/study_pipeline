# State and data files

All pipeline state lives in files under `topics/`. Machine-readable files are JSON or JSON
Lines (one JSON object per line, UTF-8). Markdown files beside them are either written by a
model for humans (`brief.md`, `check.md`, `summary.md`) or generated by `tools/state.py`
(`roadmap.md`, `glossary.md`), and generated files are never edited by hand.

## Layout

```
topics/
  .current                     plain text: slug of the active topic
  <slug>/
    state.json                 roadmap and progress, the source of truth
    roadmap.md                 generated from state.json
    sources.jsonl              topic-wide source library (S-ids)
    glossary.jsonl             every term marked so far (generated from chapters)
    glossary.md                generated from glossary.jsonl
    pitfalls.md                errors found by /errata, read by future checks
    work/                      scratch for /topic scouts
    chapters/
      NN-<chapter-slug>/
        brief.md               what this chapter must cover
        facts.jsonl            grounded facts (F-ids), cited as [@F3]
        chapter.md             the chapter (see style/FORMAT.md)
        check.md               claim-check report
        summary.md             ~200 words: what the reader now knows
        chapter.pdf            light theme
        chapter-dark.pdf       dark theme
        lab/<name>/            one directory per lab
        work/                  scratch: scout outputs, drafts
```

`NN` is the chapter number zero-padded to two digits.

## state.json

```json
{
  "slug": "raft",
  "title": "Raft consensus",
  "created": "2026-10-11",
  "goal": "One paragraph: what expertise the learner should have at the end.",
  "lab": {
    "runner": "local",
    "toolchains": ["go"],
    "notes": "Labs are small Go programs that simulate a cluster in one process."
  },
  "parts": [
    { "title": "Why consensus is hard", "chapters": [1, 2] }
  ],
  "chapters": [
    {
      "n": 1,
      "slug": "why-consensus",
      "title": "Why agreeing is hard",
      "part": 0,
      "core_ideas": ["...", "..."],
      "prereqs": ["what the reader must already know, in plain words"],
      "words": [4000, 6000],
      "status": "pending",
      "quiz": null
    }
  ]
}
```

- `lab.runner` is the topic default: `none`, `local` or `vng`. A lab can override it.
- `parts[].chapters` lists chapter numbers. Chapter `part` is the index into `parts`.
- `status` is one of `pending`, `known`, `in_progress`, `done`. `known` means the learner
  already knows it and the chapter is skipped.
- `words` is the prose budget `[min, max]`, excluding code and answers.
- `quiz` is `null` or `{"date": "YYYY-MM-DD", "solid": [...], "shaky": [...]}`.

## sources.jsonl (topic level)

```json
{"id": "S1", "title": "Atomic Commit In SQLite", "url": "https://www.sqlite.org/atomiccommit.html", "kind": "docs", "version": "page updated 2026-04-21", "why": "Primary account of SQLite's crash-safety assumptions."}
```

- `kind` is one of `paper`, `docs`, `source`, `book`, `spec`, `article`, `video`, `man`.
- `version` pins what was read: a release, tag, commit, date or edition. Use `""` if none.
- `url` may be empty for books. Then put the edition in `version`.

## facts.jsonl (chapter level)

```json
{"id": "F1", "source": "S1", "locator": "section 2, Hardware Assumptions", "claim": "SQLite assumes by default that a sector write is not atomic.", "quote": "SQLite has traditionally assumed that a sector write is not atomic."}
```

- `quote` is copied verbatim from the source and is at most about 60 words.
- `locator` lets a human find the quote again: section, page, `file.c:123`, or timestamp.
- `claim` is one sentence in plain words. It may be narrower than the quote, never wider.

## Scout output files

Scouts write `work/scout-<k>.jsonl`, one record per line, with local keys instead of ids.
`tools/state.py merge` assigns ids, dedupes sources by normalized URL against the topic
library, and appends:

```json
{"type": "source", "key": "sqlite-ac", "title": "...", "url": "...", "kind": "docs", "version": "...", "why": "..."}
{"type": "fact", "source": "sqlite-ac", "locator": "...", "claim": "...", "quote": "..."}
```

A fact's `source` is either a local `key` from the same file or an existing `S` id.

## glossary.jsonl

```json
{"term": "write-ahead log", "def": "An append-only file ...", "chapter": 4}
```

`term` is the `key` attribute if present, else the marked text, lowercased unless it is an
acronym or proper noun.

## Labs

```
lab/<name>/
  lab.json        {"runner": "local", "expect": "success", "timeout": 60, "network": false}
  run.sh          entry point, run with bash from inside the lab directory
  ...             source files
  run.out         combined stdout and stderr of the last run (written by tools/lab.py)
  run.status.json {"ok": true, "exit": 0, "expect": "success", "runner": "local",
                   "duration_s": 1.2, "hash": "<sha256 of lab inputs>", "ran_at": "..."}
```

- `runner` is `local` (sandboxed with bubblewrap, no network unless `network` is true),
  `vng` (a virtme-ng VM booting the host kernel, root inside the guest), or `none` (shown
  but never run, and its output may not be included). Omitted fields fall back to the
  topic `lab` defaults and then to `local`, `success`, `60`, `false`.
- `expect` is `success` (exit 0) or `failure` (non-zero exit, for "watch this get
  rejected" examples).
- `hash` covers every file in the lab directory except `run.out` and `run.status.json`,
  so a stale output is detectable.
